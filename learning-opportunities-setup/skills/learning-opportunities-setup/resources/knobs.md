# Preference knobs

What each setup choice controls. Load only when facilitating the interview or writing overrides.

| Knob | What it controls |
| --- | --- |
| Offer timing | Passive skill vs active interrupt in their flow |
| Cap + decline | Protects shipping days without killing the habit |
| Background + scaffolding | Right difficulty (expertise reversal effect) |
| Exercise style | Trace-the-path / mental models vs trivia quizzes |
| Auto-hook hard stop | Post-commit nudges from `learning-opportunities-auto` get answered before other work continues |
| Questions only when stopped | Retrieval happens when they can think, not mid-tool-loop |
| Completed / declined notes | Durable trail without forcing docs on every skip |
| Weekly write-only log | Spaced retrieval later without polluting session context |

## Sensible defaults (when the user is unsure)

- Offer after significant work; ask before starting an exercise
- Cap: 2 per session; decline → no more offers that session
- Prefer exercises tied to current work over abstract examples
- Fade scaffolding as they navigate independently; tighten when they struggle
- Completed notes: optional; declined notes: ask once
- Weekly log: off unless they want Friday-style retrieval
- Prefer local/gitignored override files for personal prefs
