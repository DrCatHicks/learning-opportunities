# Preference knobs

What each setup choice controls. Load only when facilitating the interview or writing overrides.

| Knob | What it controls |
| --- | --- |
| Path speed | Quick (~3 min defaults) vs full interview |
| Offer timing | Passive skill vs active interrupt in their flow |
| Cap + decline | Protects shipping days without killing the habit |
| Codebase role | Orienting / contributing / owning → scaffolding depth |
| Background + scaffolding | Right difficulty (expertise reversal effect) |
| Exercise style | Multi-select bias only when they opt in; else keep core skill mix |
| Interaction prefs | Optional plain restate, no quiz vibe, wait time, show paths — never probe |
| Auto-hook hard stop (C6) | Post-commit nudges get answered before other work continues |
| Questions only when stopped (C7) | Retrieval when they can think, not mid-tool-loop |
| Storage | none / daily / rolling log / **both** — none is a successful outcome |
| Write-only weekly log | Spaced retrieval later without polluting session context |
| Archive | Full path only — history file after clearing weekly log |

## Sensible defaults (quick path / when unsure)

- Offer after significant work; ask before starting an exercise
- Cap: 2 per session; decline → no more offers that session
- Keep the core skill's exercise-type mix (no single-style bias)
- Map A4/Q2 role to scaffolding: orienting → more guided; owning → more hunt; contributing → middle
- C6 hard stop: yes if they use auto; C7 questions only when stopped: yes
- Storage: **none** unless they choose otherwise
- Declined notes (if any logging): ask once
- Weekly log: write-only during sessions if they chose a rolling log
- Prefer local/gitignored override files for personal prefs
- Primary override path only; optional copy to a second tool at the end

## Non-goals for defaults

- Do not invent project-specific sticky prompts
- Do not require weekly retrieval rituals
- Do not lead with a specific notes app
- Do not dual-write instruction files unless they ask
